## Introduction

The goal of this methodology is to create a sound system with functional requirements that are complete and accurate.

## System Requirements Engineering (SRE)

1. Define clear, concise goals for each module or subsystem.
2. Identify all interfaces between modules/subsystems.
3. Design the architecture based on these requirements and interfaces.
4. Document these decisions in a system requirements specification document.
5. Review this document to ensure it accurately represents the stakeholders' vision.

## Modular Test Development

1. Use modular testing techniques, such as mockups or test doubles, to isolate dependencies between modules/subsystems.
2. Ensure each module/subsystem has clear and concise tests that cover its functional requirements.
3. Verify these tests against the system requirements specification document.
4. Regularly review and update the system requirements specification document based on learnings from modular testing.

## Software Development

1. Use a modular design to separate concerns and reduce interdependencies between modules/subsystems.
2. Implement features through individual module/subsystem updates, ensuring each unit of work is small enough to be thoroughly tested before integration with other modules/subsystems.
3. Regularly integrate and test the entire system to validate against the overall system requirements.

## Iteration and Feedback

1. Schedule regular software development iteration cycles that allow for continuous learning from testing and refactoring efforts.
2. Regularly solicit feedback from project stakeholders on progress, results of testing, and system requirements updates.
3. Use this information to guide further modifications and improvements in future iteration cycles.
