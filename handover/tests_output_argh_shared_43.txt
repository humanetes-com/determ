### Genesis

#### Purpose and Application

The purpose of this methodology is to guide software developers in creating accurate functional requirements that are comprehensive, complete, and correctly specified. It applies to any programming language, software development project, or testing scenario.

#### Analysis Process

1.  Review the test results for each iteration, noting which tests failed and what caused those failures.
2.  Identify the generic reasoning errors leading to these specific shortcomings in the functional requirements. Focus on identifying categories of missing or incorrect functionality, rather than discrete functions or features.
3.  Update the initial analysis process in this document (genesis.md) to address the identified deficiencies.

#### Steps for Creating Accurate Functional Requirements

1.  Understand the task at hand: what is being tested and what does it aim to accomplish? Identify the critical components that must be met, the key requirements for success.
2.  Develop a comprehensive list of anticipated user interactions with the software. Consider both standard cases (happy paths) as well as edge conditions and exceptions.
3.  Determine expected input, output, behavior, and potential error conditions. Address any limitations in the test scenarios or tools that may hinder complete coverage.
4.  Use the categorization system to identify gaps:
    *   **Functionality**: Any missing, incomplete, or inaccurately described features or functionality in the software under test.
	*   **Edge Conditions**: Oversights related to how the system handles its limits (e.g., full capacity, maximum allowed values).
	*   **User Interface Issues**: Missing information, incorrect labels, confusing interactions, or other usability problems that impede users' ability to accomplish their tasks efficiently or understand expected outcomes.
5.  Based on this analysis:
    *   Consider extending the design of tests to cover missed scenarios and conditions in step "Determination".
	*   Review test coverage and effectiveness, ensuring each category of missing details is adequately covered by tests.

#### Continuous Improvement

To ensure ongoing quality and comprehensiveness:

1.  Regularly review feedback from stakeholders after release or iteration milestones.
2.  Revise the analysis process as needed to capture improvements in software development methodologies.
3.  Maintain detailed records of previous iterations, keeping track of lessons learned to apply insights towards future requirements writing.

### Conclusion

Effective creation and evaluation of accurate functional requirements are fundamental to successful software development projects. This methodology's focus on identifying broad categories of missing details allows for an enduring, project-agnostic approach to ensuring comprehensive requirements specification.
