# Functional Requirements Methodology

This methodology ensures that a project's functional requirements accurately reflect its functionality, even when there are missing or incorrect functions.

## Analyze Test Results

1. Examine test failures to identify which tests failed and what they reveal about the requirements.
2. Trace each gap back to the reasoning process in genesis.md:
	* Identify which step produced an incomplete or incorrect requirement.
	* Understand why it was missed or introduced an error.
3. Classify the reasoning error:
	* Determine the class of error, such as not accounting for a category of test signals.

## Define and Correct Requirements

1. Generalize the lessons learned from failure analysis into specific methodological updates:
	+ Create precise and complete requirements that address each identified type of error.
	+ Incorporate the key to preventing similar errors in future projects.

## Avoid Project-specific Patches

1. Maintain a language-agnostic approach, focusing on functional requirement process rather than specifying code or language implementations.
2. Ensure updates remain general enough to address any project, regardless of programming language used.
